程序员的迷之自信与日常崩溃

发表于2026-05-23|更新于2026-05-23|杂谈
|浏览量:

写在前面

如果你身边有一个程序员朋友，请善待他。因为他每天都要经历从”我就是神”到”我是谁我在哪”的过山车式心理波动。

阶段一：信心爆棚

早上九点，端着一杯咖啡坐到工位前。

产品经理走过来：”这个需求大概多久能做完？”

你看了一眼需求文档，微微一笑：”简单，两天搞定。”

产品经理走后，旁边的同事老张凑过来小声说：”你连代码库都没打开。”

你淡定地嘬了一口咖啡：”这个功能，不就是 CRUD 嘛，我闭着眼睛都能写。”

——这是你当天最后一次开心。

阶段二：开始怀疑

两个小时后，你发现这个”简单”的功能依赖于一个三年前离职的同事写的模块。

那个模块的注释写着：

你盯着注释看了三十秒，然后默默打开了那个 2000 行的”临时方案”。

没有文档。没有注释。变量名叫 aaa、bbb、ccc1、ccc2、cccFinal、cccFinalFinal。

你的咖啡凉了，心也凉了。

阶段三：玄学时刻

你终于搞懂了那个临时方案，开始写自己的代码。写完之后运行——报错了。

你检查了语法，没问题。

你检查了逻辑，没问题。

你检查了依赖，没问题。

你删掉了一行无关紧要的空格，重新运行——跑通了。

你的表情：😀 → 😧 → 🤔 → 🙃

你决定不去追究原因，因为你知道，有些 bug 的出现和消失，都是量子力学的范畴。代码能跑就别动，这是祖训。

阶段四：现实暴击

下午四点，你自信满满地提交了代码。

五分钟后，测试妹子发来消息：”你那个功能有点小问题哦~”

“小问题”是程序员最害怕的三个字。因为测试口中的”小问题”，翻译过来通常是——整个功能都崩了。

你打开测试环境，发现你的代码在本地完美运行，但在服务器上把用户登录模块搞挂了。

你不理解。你改了文章模块的代码，为什么登录会挂？

后来发现是因为你在文章模块引了一个工具类，那个工具类改了全局配置，影响了登录的加密逻辑。

你坐在椅子上，开始思考转行送外卖的可行性。

阶段五：绝地求生

晚上七点半，你终于修好了所有问题。

测试妹子：”OK了，可以上线了~”

你颤抖着点下合并按钮，然后在群里发了一句：”已上线，有问题随时找我。”

这句话的真实含义是：求求你们别找我了，我想回家撸猫。

程序员的迷之定律

经过多年摸爬滚打，我总结了以下定律：

  1. 90-90 法则：前 90% 的代码花了 90% 的时间，剩下 10% 的代码又花了 90% 的时间。
  2. 调试守恒律：你花在找一个 bug 上的时间，和你一开始觉得”这不可能有问题”的程度成正比。
  3. 周五定律：所有紧急 bug 都会在周五下午 4:55 被发现。
  4. 演示效应：凡是给老板演示的功能，必崩。私下跑得好好的，一有人看就炸。
  5. 注释的真实含义：
    • // TODO = 我这辈子不会做的
    • // FIXME = 我知道有坑但我不想填
    • // 临时方案 = 永久方案
    • // 这里不要改 = 我试过了，改了会炸

最后的话

如果你不是程序员，看完这篇文章，希望你能理解为什么你的程序员朋友有时候看起来精神恍惚、脾气暴躁、头发稀少。

如果你是程序员，那就不多说了——快去看看你的代码在生产环境跑得怎么样吧，别在这刷博客了。

本文纯属娱乐，如有雷同——那说明你也是个苦命的程序员。
